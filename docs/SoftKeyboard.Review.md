# SoftKeyboard 检查记录

检查日期：2026-09-12。范围为动态设置、输入法布局查询、日语／注音附加面板、候选提交及相关回归。

## 实现与检查依据

- 默认设置入口使用库内 `DropDownButton`，以设置提供器生成的不可变菜单树呈现 `MenuItem`、`RadioMenuItem` 和分隔线。开关策略独立，布局选择按输入法配置记忆；图标、文字、样式可定制，提供器失败回退默认菜单。
- 设置菜单不获取编辑器焦点；等价的原生状态轮询不重建菜单容器，避免丢失已排队的点击。真实菜单打开、选项点击、关闭后输入均已验证。
- 查询 `ITfFnGetPreferredTouchKeyboardLayout`，未知或不可用返回空值。现代微软注音的精确配置标识提供有限回退，其他台湾输入法不会仅凭语言被当作注音。
- 日语 50 音、12 键通过 IME 组合输入；Windows 的假名映射用于适配键盘配置。注音面板使用标准 41 键和普通 Down 导航，输入法关闭后回到字母布局。Down 不保证发布候选，微软说明中的原生选字窗口不能作为自定义键盘接管成功的依据。
- WPF 本地源码用于确认菜单焦点、输入文档及转换模式行为。日语面板通过 IMM 桥接明确设置全角平假名／假名键模式，因为 WPF 的转换状态合并逻辑不能可靠清除 Roman 标志。
- 小狼毫非行内预编辑时只向本机 WPF 文档写入占位空格，候选元素没有标准 reading 信息接口，隐藏它的原生窗口会丢失拼音预览。`CandidateMode.Automatic` 因此在 BeginUIElement 时保留小狼毫原生窗口；设置菜单允许明确选择 Native 或 Embedded，当前内嵌元素保持到结束后再完整应用新策略。
- 小狼毫显式内嵌模式使用当前页数字键一次提交。`SetSelection` 只改变 UI 高亮，`Finalize` 未执行引擎候选选择，集成接口 `OnKeyDown` 也没有实际处理，依据为其 `WeaselTSF/CandidateList.cpp`。当前页最多 9 项时映射到 1–9；不逐项移动，不补空格，重复点击不追加数字。需要可见预编辑时，用户须在输入法侧开启 inline_preedit；控件不改写用户配置。

## 验证结果

- 定向回归共 200 项：192 项通过，0 失败，6 项原生输入法测试默认跳过，2 项既有显式测试未执行。范围包含 VirtualInput、RadioMenuItem 和 DropDownButton。
- 单独启用本机原生输入法测试：验证微软日语两种面板输入、小狼毫自动模式保留原生候选窗口（IsShown）及空格确认，显式内嵌模式通过真实候选按钮选择不同位置、重复点击及部分转换后的连续选词。完整候选点击提交有 500ms 内完成的断言，另观察选中索引更新，检查没有逐项移动到中间候选。
- 6 个原生用例按独立进程执行全部通过；同进程整组执行曾有 3 项失败，并观察到前序输入进入后续编辑器，属于仍需排查的会话切换／测试隔离问题。验证命令明确按进程隔离，不将整组失败隐藏成全通过。
- 注音固定使用 Profile B2F9C502-1742-11D4-9790-0080C882687E：输入 ㄋ、ㄧ、ˇ 后，文本框为“你”、候选为空；再按 Down，得到 9 项内嵌候选“你／妳／擬／隬／旎／昵／伱／伲／儗”，点击确认通过。软键盘与编辑器同时加载、编辑器先加载两种顺序均通过，候选截图已检查。该结果是有限场景复现，不代表用户报告的注音无候选问题已修复。
- 原生测试还验证 IME 开关后的布局、真实设置菜单选择，以及切换输入法后恢复所选布局。三个面板截图已检查，无底部裁切。
- VirtualInput 的 `net8.0-windows` / `net472`、Gallery 的 `net10.0-windows` / `net472` 与测试项目构建通过。仓库仍存在其他分析器和文档警告，不宣称整个仓库零警告。
- 使用编译后的 xUnit 运行器；未改变仓库现有 Microsoft Testing Platform / VSTest 配置。复现命令见 [SoftKeyboard.md](SoftKeyboard.md)。

## 当前边界

- 12 键通过长按浮层选择其他假名，未实现滑动手势或多击轮换。
- 日语面板输入会保留全角平假名／假名键模式，随后硬件键盘沿用该模式；这不是只改变键帽显示。
- 原生测试验证本机已安装输入法。小狼毫的自定义数字绑定、其他 Windows／IME 版本仍需各自验证；数字提交 750ms 未观察到候选变化时提供 `CandidateCommitError`，不重复发送或追加其他确认键。
- 已复现单个 `ㄋ` 和随后 Down 均无候选；未完成音节的实时候选仍未实现。微软注音的函数提供器返回 `0x80040503`，系统提供器不支持 `ITfFnSearchCandidateProvider` / `ITfFnGetLinguisticAlternates`（`E_NOINTERFACE`），本机这两个公开查询渠道不可用。系统触摸键盘显示候选不代表普通桌面 TSF 会话必然发布相同候选；具体内部机制仍未确认。
- 布局选择保存在控件实例内；跨进程持久化由应用负责。
- 前台输入检查依赖 WPF Window，不能据此宣称支持无 WPF Window 的 ElementHost 宿主。多指、手写笔、混合 DPI 和屏幕阅读器仍需专项实机验证。
