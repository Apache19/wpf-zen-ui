# 软键盘首次构造耗时复核

测量日期：2026-09-21。基线提交：`7d387eba`。
前文保留本轮优化前的诊断记录；临时分段计时代码已撤回。后续按需布局优化和复测见文末。

## 结论

设置功能移除之后，构造函数仍调用 `RebuildLayout()`，同步生成默认字母布局。
这是剩余开销最大的路径。注册按键事件还会触发 `SoftKeyboardKeyControl` 类型初始化，
其中包含暂时用不到的 Popup 属性描述器初始化。

首次进入需要支付这些路径的方法编译、类型初始化、WPF 属性/事件注册和首次对象构建成本。
同一进程后续实例远快于第一次，不能把冷启动成本等同于每次生成 36 个键模型都需要几十毫秒。
本次没有发现设置树、输入法目录枚举或候选会话创建重新进入构造路径。

## 测量边界

- 使用现有隔离宿主，预载图库和控件资源，先创建隐藏在屏幕外的 WPF 窗口，再测量键盘。
- `IsOpen=false`，无扩展提供器赋值、无编辑器输入、无输入法切换。
- 每种条件启动三个独立进程，进程内另测后续实例。
- `Stopwatch` 测量外部 `new SoftKeyboard()`；分段实验将时间戳暂存在内存，结束后再输出。
- 数值是当前机器的墙钟耗时，不是采样分析器的独占 CPU 时间；分段包含下游初始化和 JIT。
- 不包含后续模板、Measure/Arrange、Loaded，也不是完整图库导航时间。

## 当前未插桩版本

| 条件 | 三个进程的首次构造 |
| --- | --- |
| Release，分层编译启用 | 29.328 / 25.337 / 25.859 ms |
| Debug，分层编译启用 | 33.462 / 28.848 / 31.451 ms |
| Release，分层编译关闭，与之前报告测法一致 | 46.604 / 44.651 / 43.214 ms |

Debug 中后续实例为 0.283–0.434 ms；Release 后续实例多数低于 0.7 ms，
分层编译启用的记录中有一次 1.855 ms 的波动。因此旧报告中的约 45 ms 与当前约 25–33 ms
不是相互矛盾，编译配置和首次路径预热程度会显著影响结果。

原有 Debug `Constructor` 日志只从内部构造函数体开始计时。
本次日志为 22.723–25.193 ms，而外部 `new` 为 28.848–33.462 ms；
日志不包含进入该函数体之前的完整类型初始化、基类构造和首次编译成本。
日志中的 `RebuildLayout` 为 19.080–21.590 ms，已经能解释大部分构造函数体耗时。
嵌套日志不可相加。

## 首次路径分解

为了与此前数据对应，下表使用 Release、关闭分层编译的分段实验。
这些区间按调用链顺序记录，包含调用路径第一次使用时的编译和初始化，不能全归为算法执行时间。

| 路径 | 观测值 | 说明 |
| --- | --- | --- |
| 单独预先触发 SoftKeyboard 类型初始化 | 约 7 ms | 依赖属性、默认值依赖、命令和元数据注册 |
| 构造中的按键类型初始化 | 约 3.7 ms | 引用按键 RoutedEvent 触发类型初始化 |
| 其中 Popup 属性描述器 | 2.73–2.82 ms | `DependencyPropertyDescriptor.FromProperty(Popup.IsOpenProperty, typeof(Popup))` |
| 默认布局前的扩展解析 | 4.91–5.11 ms | 空扩展也建立标准布局注册、可选布局快照及标准提供器依赖 |
| 默认布局提供器调用 | 约 20 ms | 布局分派、物理字母、功能键和布局构建器的首次调用链 |
| 当前输入语言读取 | 0.08–0.09 ms | 不是这次的主要阻塞点 |
| 26 个字母标签解析合计 | 0.62–0.66 ms | 包含首次调用准备；不等于原生 API 的独占时间 |

默认布局内部还观察到：进入字母布局方法前约 7.7–7.8 ms，
物理字母工厂进入首个键回调前约 4.4–4.9 ms，布局构建器处理行约 3.5 ms。
后续键的标签解析和模型构造通常只有几微秒。
这些分段与同进程后续实例显著变快、分层编译实验一致，说明首次代码准备占有较大比例；
本次未使用 JIT 事件追踪，不能据此声称得到了精确的 JIT 独占耗时。

布局生成仍调用 `GetKeyboardLayout`、`MapVirtualKeyEx`、`ToUnicodeEx`，用于当前键位标签。
这些操作与枚举已安装输入法目录是不同路径；26 个字母标签解析合计不足 1 ms，
不支持把它们视为此次几十毫秒的主要原因。

## 交叉验证

先单独调用一次默认布局生成，再构造键盘：

- 第一次布局生成：21.884–22.297 ms。
- 随后的键盘构造：21.518–21.845 ms。
- 同进程第二个键盘：0.273–0.454 ms。

提前执行并未减少这两步的总成本，只把其中一部分从构造函数转移出去。
因此不建议以启动时同步预热作为解决页面冻结的主要办法。

## 诊断时提出的优化优先级

1. **让关闭状态不生成布局。** 构造和关闭状态下的配置回调只标记布局失效，
   首次打开或应用显式 `RefreshLayout()` 时生成一次最新布局，避免先生成默认布局再被 XAML 配置替换。
   这需要同时梳理 `CurrentLayout` 和布局目录的初始语义、模板绑定和自动化访问；
   仅删除构造末尾一行不足以形成完整方案。
2. **按键事件处理器在需要按键表面时接入。** 避免仅构造关闭的键盘就初始化按键控件类型；
   需防止重复注册并保留模板替换行为。
3. **Popup 属性描述器在实际连接 Popup 时取得。** 当前静态字段在引用按键事件时就初始化，
   与 Popup 的真实使用时机不一致。这属于独立的小优化。
4. **精简默认布局的首次调用链和临时对象。** 可以评估部分 LINQ 分派、重复数组复制和行校验包装，
   但优先级低于直接跳过关闭状态不需要的整个布局生成过程。

前两项主要减少首次进入关闭页面的成本；首次真正打开键盘仍需要支付布局和模板准备成本。
本次没有修改这些生命周期契约。

## 已实施：按需布局与按键初始化

- 构造函数不再调用 RebuildLayout，也不引用按键控件的路由事件。
- CurrentLayout 初始为共享的 SoftKeyboardLayout.Empty，包含零个按键、一个逻辑列。
  AvailableSupplementalLayouts 初始为空。属性读取没有隐式初始化副作用。
- 关闭期间的配置变化只标记布局失效。重新打开时按最新配置生成；已生成的快照在关闭期间保留。
  显式 RefreshLayout 可在未加载或关闭状态生成布局及可选布局目录。
- 按需入口与 BuildLayoutCore 分离，关闭路径不会首次编译整段布局工厂。
- 输入法操作期间仍协调布局发布；首次展示可以先生成已提交上下文的基础布局，
  后续布局更新等待观察稳定。递归刷新不会把显式请求泄漏到下一次关闭状态的配置变更。
- 首次打开时注册按键路由处理器，模板重新应用和再次打开均不会重复注册；
  派生控件默认打开时，模板应用也会完成初始化。
- Popup 属性描述器移至独立的延迟初始化类型，仅在实际连接 Popup 时取得。
- 图库菜单显式刷新布局目录，应用仍通过公开属性和布局 API 配置键盘。
  附加布局选择重新验证失效目录，并保留组合取消与按输入法记忆。

### 同条件复测

继续使用相同隔离宿主，每个条件启动三个独立进程，不附加调试器。
以下为未插桩产品代码，布局生成和输入法目录均保持未请求状态。

| 条件 | 优化前首次构造 | 优化后首次构造 | 中位数变化 |
| --- | --- | --- | --- |
| Release，分层编译启用 | 25.337–29.328 ms | 5.379–7.441 ms | 25.859 → 5.614 ms，降低约 78% |
| Release，分层编译关闭 | 43.214–46.604 ms | 9.856–10.052 ms | 44.651 → 9.986 ms，降低约 78% |
| Debug，分层编译启用 | 28.848–33.462 ms | 6.809–10.615 ms | 31.451 → 6.907 ms，降低约 78% |

计入随后挂载、首轮布局及排空 Loaded 的总耗时，中位数分别为：

- 分层编译启用：107.373 → 88.047 ms，降低约 18%。
- 分层编译关闭：141.924 → 107.615 ms，降低约 24%。

挂载阶段仍有约 77–92 ms 的框架/模板初始化成本，构造下降不等于页面导航总成本同幅下降。
关闭页面稳定等待后，模型按键、按键控件、输入法目录均为零。

首次真正打开仍需要生成布局和模板：一次打开/关闭冒烟记录中，首次打开并完成布局为 163 ms，
再次打开为 46 ms，均生成 37 个键模型及 37 个按键控件。
这些单次记录用于确认显示链路正常，不作为打开性能改善的统计结论。
本轮解决的是关闭状态下不必要的初始化；没有把首次展开成本视为已经消除。
